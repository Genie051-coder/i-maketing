## 1. 과제 개요

이 과제는 실제 운영 중인 이메일 마케팅 플로우 빌더 (`i-marketing`) 코드베이스를 이해하고,  
주어진 기능 개선 요구사항을 구현한 뒤 결과를 정리·발표하는 과정입니다.

| 구분 | 내용 |
|------|------|
| **프로젝트** | i-marketing — 이메일/SNS 캠페인 플로우 빌더 |
| **스택** | Next.js 15, React 19, TypeScript 5, Zustand 5, Prisma 5, Tailwind CSS v4 |
| **총 시간** | **2시간** |
| **메인 과제** | `FEATURE_INLINE_EDIT_AUTOSAVE.md` 구현 |
| **보너스 과제** | `FEATURE_EMAIL_PREVIEW.md` 구현 (시간 여유 시) |
| **필수 산출물** | 개발 결과 보고서 (1시간 40분 내 완성) |

- 사용자가 `/ko` 홈에서 캠페인을 생성하고 이메일을 발송하는 전체 흐름을 확인합니다.
- 각 단계에서 어떤 노드(Node)가 사용되는지, 화면 다이어그램을 통해 UI 구조를 파악합니다.

### Step 2. 실제 유스케이스 체험 → `useCase1.md` 따라하기

- 앱을 직접 실행하여 `useCase1.md`의 단계를 따라가며 실제 UX를 경험해보세요.

## 3. 개발 과제 (메인)

### 메인 과제 — `FEATURE_INLINE_EDIT_AUTOSAVE.md` 구현

요구사항 문서: **`FEATURE_INLINE_EDIT_AUTOSAVE.md`**

두 가지 이슈를 해결합니다.

#### 이슈 A. 텍스트 인라인 편집 불가 개선

- **현재**: 이메일 미리보기 영역의 Text 블록을 클릭해도 직접 타이핑 불가. 우측 패널 → 블록 편집 탭에서만 수정 가능.
- **목표**: Text 블록을 **더블클릭** 하면 그 자리에서 바로 텍스트 입력 가능 (인라인 편집).

**핵심 수정 파일**
```
src/features/nodes/email-create/ui/EmailDropZone.tsx
src/features/nodes/email-create/EmailConfig.tsx
```

#### 이슈 B. 노드 자동저장 미구현

- **현재**: 이메일 에디터 노드에서 "노드 저장" 버튼을 클릭하지 않으면 내용이 저장되지 않음.
- **목표**: 입력 후 **800ms 비활동** 시 자동으로 DB에 저장. 저장 상태를 헤더에 표시.

**핵심 수정 파일**
```
src/features/nodes/email-create/EmailConfig.tsx
src/shared/ui/components/DynamicModalHeader.tsx
src/features/nodes/email-address-book/AddressBookConfig.tsx
src/features/nodes/email-send-settings/SendSettingsConfig.tsx
```

> 구체적인 구현 방법, Props 변경, 코드 스니펫은 `FEATURE_INLINE_EDIT_AUTOSAVE.md` 의 각 섹션을 참고하세요.

## 6. 본부장 발표 및 피드백 대응

### 발표 내용 구성 (권고)

1. **프로젝트 이해** — 어떤 앱인지, 어떤 흐름으로 동작하는지 간략히 설명
2. **버그 재현** — 수정 전 문제 상황을 직접 시연 (or 설명)
3. **구현 내용** — 어떤 접근으로 해결했는지, 핵심 코드 설명
4. **시연** — 수정 후 동작 시연
5. **미완성 항목** — 구현 못 한 부분과 이유, 접근 방향

### 피드백 대응 원칙

| 상황 | 대응 방법 |
|------|-----------|
| 코드 수정 요청 | 즉시 수정 후 재시연 |
| 다른 방법 제안 | "네, 그 방법으로 수정하겠습니다" → 빠르게 적용 |
| 이해 못 한 부분 | "다시 한번 설명해 주시겠어요?" 정중하게 재확인 |
| 미완성 부분 질문 | 준비한 접근 방향을 설명, 시간 내 구현 계획 제시 |
